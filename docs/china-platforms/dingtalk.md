# 钉钉文档接入方案

## 接入目标

- 打通钉钉企业应用授权后，读取企业内文档目录与文档正文
- 首期支持“目录遍历 + 文档正文抽取 + 基础元数据”

## 鉴权与配置

### 凭证字段（建议）

- `app_key`
- `app_secret`
- `root_space_id` 或 `folder_id`
- `max_folder_depth`（可选）

### 鉴权流程（待平台细化）

1. 企业应用凭证换取 access token
2. 按 API 要求附带 `x-acs-dingtalk-access-token` 或 Bearer
3. token 失效自动续期

## 接口适配内容（计划）

### 空间与文件发现

- Space 列表接口（定位知识空间）
- 文件/目录列表接口（递归遍历）

### 内容拉取

- 文档详情接口（标题、创建/更新时间、作者）
- 文档正文/导出接口（优先纯文本或可解析格式）

### 实体映射（MVP）

- `DingTalkDocEntity`
  - 主键：文档 token/id
  - 字段：标题、正文、空间 ID、路径、时间戳、url

## 遇到的问题与风险

- 钉钉开放能力在不同应用类型下差异明显
- 企业认证/审核流程可能影响开发节奏
- 文档内容接口可能存在格式分裂（需做转换层）

## 验证清单
