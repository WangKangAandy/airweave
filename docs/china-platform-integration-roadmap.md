# Airweave 国内平台接入 Roadmap

## 目标

构建一套适配国内主流知识平台的统一接入能力，支持：

- 统一授权配置（API Key / OAuth / App Credentials）
- 文档加载与解析（优先文本型，逐步扩展附件与富媒体）
- 可观测、可限流、可增量同步
- 与 Airweave 现有 Source 框架一致（配置、实体、同步、错误处理）

## 范围与优先级

### P0（先落地）

- 飞书文档（Docx + Drive Folder）
- 钉钉文档（Drive/Space/File）

### P1（能力增强）

- 语雀知识库（文档/知识库结构）
- 企业微信知识库/文档（按开放能力确定最小可用范围）

### P2（高级能力）

- ACL/权限继承
- Wiki/知识空间全量拓扑
- 富媒体与附件抽取（图片 OCR、表格结构化）

## 统一适配规范

每个平台适配均按以下模块落地：

1. 认证层：凭证字段、换 token、过期刷新
2. 发现层：空间/目录/文件遍历
3. 内容层：正文拉取、元数据提取、实体建模
4. 同步层：全量 + 增量游标 + 删除检测
5. 稳定性：限流、重试、幂等、降级
6. 可观测：结构化日志、指标、失败分类

## 里程碑（建议 8-10 周）

### M1（第 1-2 周）：框架统一与飞书 MVP

- 飞书最小闭环（folder -> docx -> raw_content -> entity）
- 文档化接口映射、错误码映射、限流策略
- 加入基础集成验证脚本

### M2（第 3-4 周）：钉钉 MVP

- 钉钉企业应用授权链路打通
- Space/Folder/File 遍历 + 文档正文抽取
- 完成与飞书一致的可观测字段

### M3（第 5-6 周）：增量同步与稳定性增强

- 飞书/钉钉增量游标（modified_time 或 change log）
- 标准化重试/回退策略
- 失败重跑与部分成功提交策略

### M4（第 7-8 周）：语雀/企业微信预研 + PoC

- 完成接口能力差异评估
- 至少 1 个平台 PoC（可创建连接、可同步、可检索）
- 输出是否进入正式开发结论

### M5（第 9-10 周）：生产化验收

- 监控看板与告警阈值
- 回归测试矩阵（鉴权、限流、增量、删除）
- 发布说明与运维手册

## 风险与应对

- 开放平台权限收紧：预留“能力探测 + 功能降级”
- 频控突发：引入按接口维度限流器
- 结构不一致：统一实体抽象，平台差异下沉到 source 内部
- 授权流程复杂：优先企业内应用场景，减少外部审核阻塞

## 当前建议

先以飞书和钉钉完成“可用闭环”，并在闭环后统一补齐：

- 增量同步
- 删除检测
- ACL 能力
- 大规模同步稳定性（并发 + 限流 + 重试）
